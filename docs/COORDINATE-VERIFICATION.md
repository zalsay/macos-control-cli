# 截图坐标与点击落点验证

验证日期：2026-10-20。原生组件版本：0.1.6，protocol 1。

## 问题与结论范围

反馈现象为中文文本输入到了相邻的短标题框，怀疑点击向上偏约 128px，并猜测与控制条有关。输入到了错误控件说明需要核对焦点或坐标，不能仅据此认定系统输入被丢弃，也不能直接得出固定 `Y + 128` 补偿规则。

本机隔离测试未复现固定偏移。ScreenCaptureKit 与系统单窗口截图回退分别覆盖三种窗口几何、三个垂直位置，共 18 次图像坐标点击，实际落点误差均为 0；JPEG 色块中心与按 AX 屏幕几何计算的像素中心误差不超过 0.5px。控制条显示时的采集也在覆盖范围内。

这些结果验证指定环境下的图像内容和输入映射，不证明用户当次发布页面的具体根因。没有获得能够关联本次反馈的原始 Observe 帧、同帧 Click 参数与窗口几何，不能断言一定是调用方坐标误用。未测试 Retina、多显示器、网页缩放或不同 Chrome 工具栏布局的全部组合。

## 测试方法

运行：

```bash
bash tests/coordinate-smoke.sh /absolute/path/to/copis-chrome
```

测试使用独立临时 profile、私有 CLI runtime 和 loopback HTTP 页面。页面禁止连接外部服务和表单提交，不访问用户发布页面，不上传文件。只根据自有测试页色块执行图像协议断言，不查看或分析用户截图，不用于 Electron UI 视觉验收。结束时停止自己的 daemon 与 Chrome，恢复原前台应用。

主屏逻辑区域不足的窗口几何会明确标记 SKIP；至少一个几何必须实际执行。完整三种几何需要主屏能容纳 `(120,80,2000,1100)`。当前验证主屏为 3440×1440、scale=1：

| 窗口 bounds（逻辑点） | JPEG 像素 | 每个后端点击次数 |
|---|---|---|
| x=48, y=150, 1000×800 | 1000×800 | 3 |
| x=180, y=44, 1000×800 | 1000×800 | 3 |
| x=120, y=80, 2000×1100 | 1600×880 | 3 |

SCK 使用已激活的 0.1.6 组件。回退验证只在 `/tmp` 私有源码副本中注入主后端失败，通过 `COPIS_CHROME_HELPER` 指向单独编译的测试 Helper，以真实 `screencapture` 后端运行相同场景。没有修改安装目录、生产截图策略或正在使用的其他 runtime。

另用临时测试脚本为色块中心注入 -128px 偏差，验证图像对齐断言会在错误点击发出前失败。此负向验证证明测试能够捕获所述量级的错位；不是生产代码中的补偿逻辑。

## 调用约定

- Click / Scroll 使用**同一 Observe 返回的完整窗口 JPEG**的整数像素，原点包含标签栏、地址栏。
- 不能直接使用全屏截图像素、网页 `clientX/clientY` 或另行缩放/裁切的图片坐标。
- 全局屏幕逻辑点需要结合本帧 `bounds` 与图像尺寸转换；物理像素需要先确认其所属屏幕和缩放，不能直接代入。
- 控制条是独立窗口；没有为控制条添加固定 Y 补偿。
- 若再次发生偏移，应保留该次 Observe 的尺寸、bounds、后端和对应 Click 数值，核对实际使用的图像来源；不要凭另一张截图反推固定偏移。

本轮仅补充工具提示、接入说明和回归测试，没有修改原生点击映射、放宽输入归属检查、改变帧复用规则或升级原生模块版本。实际用户页面仍需用户确认；未代替用户做 Electron UI 验收。
