# 三秒接管倒计时验证

日期：2026-10-20。组件版本：0.1.7，JSON protocol 1。

## 行为

- 只读 Observe 不切前台，也不启动接管倒计时。
- 首次输入先显示「AI将在 3 秒后接管，请松开鼠标」，按 3 → 2 → 1 自动进入运行，不要求点击执行。
- 倒计时没有输入副作用，鼠标移动和应用切换不触发接管暂停。控制条提供「取消」，取消后保持暂停，不会在原截止时间自动恢复。
- 运行后鼠标接管和切走应用仍暂停后续输入。点击「继续」后重新倒计时三秒，不立即恢复。
- 取消、断开和 EOF 使旧 lease/输入代次失效；暂停前和暂停期间排队的旧输入不会因继续而重放。
- 原有权限、精确窗口身份、焦点、窗口几何和指针归属校验保留。输入等待结束后仍须通过这些校验。

## 实现边界

三秒的输入门禁由原生 core 的单调时钟 deadline 决定，UI timer 只展示状态。第一次 deadline 从控制条展示后开始，重复展示不重置。继续操作原子地更新输入 epoch 并进入新倒计时；倒计时完成不再次换代，允许其开始后到达的有效新请求等待接管。

倒计时等待发生在既有串行动作队列，不阻塞 AppKit。当前 CLI 仍为串行调用契约：输入等待期间并发工具调用可能收到 BUSY，未新增并发 Observe。暂停后普通 Observe 仍可用；cancel/EOF 不排在输入等待后。

鼠标事件使用 NSEvent 自带时间戳过滤迟到的倒计时事件。应用激活通知没有同等的事件发生时间戳，记录最早收到通知的时间及 activated PID，明确的外部激活不会被随后切回 Chrome 吞掉；身份缺失时回读真实前台。不声称能还原通知的实际发生时刻，输入仍保留原有焦点校验。

## BDD 与真实验证

```text
Given 已选定并授权本机 Chrome 窗口
When 首次发起输入
Then 显示 3 → 2 → 1，完整三秒前不能取得输入凭据
And 不需要点击执行，倒计时中的鼠标移动不会暂停

Given 正在倒计时
When 用户取消、断开或 helper 收到 EOF
Then 等待动作中断，旧截止时间与旧回调不能重新接管

Given 用户已暂停
When 经过任意时间或重新观察
Then 不自动恢复
When 用户点击继续
Then 新请求等待三秒，旧失败动作与旧输入代次仍不能执行
```

验证项目：

- Core 使用受锁保护的 fake 单调时钟，验证三秒边界、重复展示、迟到事件、等待取消、暂停保持、继续三秒门禁及旧动作不可重放；无真实输入。
- AppKit 对象回归验证 3/2/1 文案、取消/继续/暂停按钮、计时器生命周期、owner/lease 隔离、窄屏布局和非激活窗口属性；不查看截图。
- 153 项无副作用 JSONL 检查与原有焦点、指针归属、截图回退及文件对话框回归通过。
- 生产构建的 0.1.7 CLI 在独立 Chrome profile、私有 daemon/runtime 和本机无上传页面上完成真实执行控制 BDD：首次自动三秒接管、倒计时中外部鼠标移动不暂停、取消后到点不复活、继续后三秒恢复、运行中外部鼠标接管、暂停不抢前台、Observe/帧/连接保留和断开清理。

真实驱动修正了两项测试前提：AXPress 成功不代表 selector 已提交，因此等待按钮状态确认后才构造新输入；CGEventPost 返回不代表外部测试鼠标事件已送达，因此移动到不同坐标并确认全局鼠标位置更新后再退出测试进程。没有为通过测试而忽略外部事件或绕过 pause/epoch 门禁。临时诊断仅存在于 `/tmp` 源码副本；真实回归随后也在无诊断的生产二进制上通过。
