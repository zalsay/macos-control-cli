# v0.2.1 点击前鼠标轨迹

## 已确认的设计

- 从当前真实光标位置出发；读取发生在三秒倒计时、窗口激活及首轮精确检查之后。
- 三次Bézier路径，最多28个屏幕逻辑点的轻微横向弯曲；minimum-jerk时间进度 `10u³-15u⁴+6u⁵`。
- 曲线叠加该时间规律不等于严格求解任意曲线的最小急动度；目标是平滑交互，不宣称与真人不可区分。
- 距离相关时长，计划150–700ms，小幅随机时长/曲率。约60Hz采样，主机负载下不是硬实时保证。
- 终点使用CLI原先换算出的精确屏幕坐标，不增加随机偏移、过冲或目标附近抖动。
- 同点不添加虚假运动；双击只在第一下之前移动一次；不新增拖动、不改滚动、输入和按键契约。

## 安全与时序

只投递mouseMoved，不按住鼠标。开始前确认目标；每次小步等待/投递检查取消及用户暂停；移动中约每50ms检查窗口几何；焦点变化沿用原全局监听，按下前再次复核精确焦点、窗口几何与目标指针归属。实际事件提交继续受InputCancellation许可和提交锁保护。

中断后不强行到达终点、不完成点击、不重放失败动作。每步等待最长5ms；系统调度和查询延迟仍可能影响实际响应时间。调度迟到会跳过过时中间采样，避免补发成一串突发事件。

使用CGEvent/CGDisplayBounds同一屏幕坐标系，不使用NSEvent左下角原点。同屏曲线限制在共同屏幕矩形内，跨屏使用保守平滑直线；样本和相邻线段必须被有效显示区域并集覆盖。曲线越界先尝试平滑直线，仍经过多屏空洞则在投递前失败。这样调度丢弃过时点后形成的新线段也不会跨过凹角空洞。不新增绕屏障寻路或跳跃穿越空洞的规则。

## 算法与实现

`swift/CursorMotion.swift`负责纯路径生成、可见区域约束和可中断调度；`swift/Input.swift`复用原输入源、检查与投递逻辑。没有新增依赖或第二套坐标换算。

minimum-jerk依据Flash/Hogan 1985点到点运动模型；Bézier控制点用于简单几何路径。这里按批准方案自行实现，不复制第三方库代码或引入Python运行时。

## 验证范围

`tests/cursor-motion/main.swift`运行真实规划/调度函数，使用fake时钟与投递闭包，不发送系统输入。覆盖起终点、轻微曲率、起停速度、纵向不回头、时长/采样、屏幕边缘、负坐标/相邻屏、跨屏空洞拒绝、取消/暂停/失焦/窗口变化及迟到采样。

`tests/coordinate-smoke.sh`为显式桌面回归，使用私有Chrome profile与本机隔离页面，读取页面实际收到的mousemove和click事件，检查中段有连续移动、真实点击落点不变、双击之间没有重新移动。不能在另一个任务占用桌面时运行；sent:true不能替代该验证。
