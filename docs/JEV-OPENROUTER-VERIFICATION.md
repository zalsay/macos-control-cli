# OpenRouter Jev 验证与边界

本文为0.2.5–0.2.9阶段历史证据。当前v0.3.0配置与启动验证见 [v0.3.0验证](V030-VERIFICATION.md)；以下 `.env` 行为不适用于v0.3.0。0.2.5的[历史验证](JEV-VERIFICATION.md)不代表本版状态。

## 已有真实证据

- 通过项目当前目录 `.env` 中的 `JEV_API_KEY` 调用OpenRouter Decisions接口；未输出、改写或归档密钥文件。
- 合成OCR实测请求 `typesafe/jev-1.13`，返回 `typesafe/jev-1.13-20260917`，选中保存候选t0；选择概率0.98、confidence0.97、存在概率0.95，约1812ms。只是一个样例，不是正确率/延迟基准。
- 前期中文样例曾因门槛不足拒绝，另有一次连接超时。没有为了通过测试降低门槛或添加自动重试。
- 0.2.6真实Chrome登录测试：页面观察正常，“微信快捷登录”被新增OCR复核以TARGET_CHANGED拒绝，未完成登录。原生按钮框前后相同，但整页OCR条数21变24；只是过严比较的线索，未取得守卫两帧逐项差异证明。

## 用户要求的0.2.7修订

- 删除二次截图/OCR与全部专用守卫，模型选定同帧坐标后复用原有click。
- Swift输入、协议、捕获与main入口恢复接入OCR守卫前的实现；原有窗口/焦点/指针/暂停/取消门禁不变。
- 回归测试逐项比较语义点击和普通坐标点击产生的原生请求，要求完全相同，且只观察一次；不再要求守卫专用元数据。
- CLI版本握手拒绝继续复用0.2.6旧daemon，以免误跑仍有复核的旧服务。旧服务不会被自动停止。

## 尚未解决或不能外推的事项

- 先前完整并发Rust测试中，继承管道清理时限检查曾耗时约2.89秒而失败；本次不修改其实现或放宽测试要求。
- 当前执行环境里隐式后台进程曾在工具调用间停止；测试可显式运行本任务私有 `daemon run`，不能据此声称隐式后台存活问题已修复。
- 实际视频号登录重测结果以本次现场截图/投递回执和最终交付说明为准；需要用户手机扫码/确认时必须停下，不把sent:true当作登录完成。
- 未进行Intel、CI、公证或公开发布；没有修改用户已安装命令。

## 0.2.8 定向修订

按用户要求允许有效非空的截断OCR进入Jev；`state.ocrTruncated`标注上下文是否截断。原有输出预算、合法性校验、模型门槛和原生点击门禁不变。新增回归覆盖截断候选送模以及原有点击投递。此次不进行额外账号操作或网络调用。

## 0.2.9 当前请求压缩

仅发送目标和id/文字映射，去掉geometry/候选重复数据/截断标记和exists问题；完整OCR坐标仍本地保留。Choice分数/ID合法性及原生点击门禁不变。新增测试对请求字段和ID本地坐标查找逐项断言，包括同名文字仍按ID查坐标；这不证明模型能仅凭文字区分同名控件的位置。

两候选合成样例：1628 → 290 bytes（减少82.2%），不是延迟或实际命中率基准。本次没有重新进行账号操作。
