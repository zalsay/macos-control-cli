# v0.1.8 原像素采集与页面控制条

验证日期：2026-10-21。JSON protocol 保持 1；命令名称与 `frameId` 输入方式兼容。

## 本轮范围

沿用原有 Swift 原生捕获/控制条和 Rust frame 映射，不新建坐标适配层，不新增外部图片变换或裁切注册 API。原生像素规则由现有捕获入口执行，Agent 只在 Observe 图片中取点。

- 两种捕获后端保留原生像素。SCK 选择独立目标窗口，以原生 pointPixelScale 输出；系统截图回退直接解码原始窗口图像，不创建缩略图。
- 1600px 边长和小于 1MiB 的既有限制保留；超限明确失败，不缩放兜底。JPEG 编码可调质量，不改变宽高。Retina 2x 窗口超过 800×800 逻辑点时可能触发边长限制，需要缩小实际窗口后重新观察。
- Observe 的 `coordinateSpace: frame-pixels`、`imageTransform: crop-only` 仅来自当前 helper 的声明；旧 helper 缺少声明时不伪造保证，非法或不完整声明拒绝。
- 点击/滚动增加 `screenPoint`，只表示 CLI 计算并向 helper 投递的屏幕逻辑点，不表示系统实际命中或业务成功。Agent 无需计算原点、Retina 或固定偏移。
- 现有控制条下移、放大，主标题带当前目标页面名，左侧 Logo 从独立包 `assets/` 加载。标题在既有观察/输入入口刷新，不新增后台页面轮询。
- 右上角关闭先暂停/中断输入再隐藏，不解除授权、不停止只读观察。旧倒计时和观察刷新不能复活已关闭控制条；后续输入仍受暂停门禁约束，用户继续后再走既有三秒倒计时。

## BDD 契约

```text
Given 1x 或 2x 的原生窗口截图尺寸没有超出既有上限
When Observe 编码并保存图片
Then 原生像素尺寸保持不变，不通过缩放、重采样或缩略图满足限制

Given 原生截图超出 1600px 边长或 JPEG 不能编码至限制内
When Observe
Then 返回 IMAGE_TOO_LARGE，不调用输入，也不降级到缩图后端

Given 有效 frame 和非零窗口原点
When Click 或 Scroll 传入该图像中的像素坐标
Then CLI 使用 frame 的 bounds/width/height 完成映射
And screenPoint 等于传给原生 helper 的数值
And 越界、几何变化和暂停仍拒绝输入

Given 控制条正在倒计时或执行输入
When 用户点击右上角关闭
Then 先暂停输入，再隐藏控制条，旧 permit 和旧倒计时不能继续执行
And 只读观察与连接保留，观察标题刷新不会重新显示控制条
```

## 验证与验收边界

原生状态与布局使用 AppKit/纯逻辑检查；真实 CLI 验证只在独立 Chrome profile、私有 runtime 和本机无上传 fixture 上执行。允许读取固定测试色块来核对原像素与映射协议，不读取用户业务截图，不把自动化检查当成 Electron UI 验收。

原有三秒倒计时、暂停前/暂停期间旧动作不重放、精确窗口/焦点/几何/双源指针校验、32 帧复用和无时间硬过期都应继续通过回归。

控制条的实际位置、双行文字、Logo 清晰度和关闭按钮的真实手感，仍由用户在实际窗口确认。

## 本机实际采集与未完成的桌面验收

在独立 Chrome profile、私有 runtime 与本机固定色块页面上，SCK 原生采集完成两种窗口原点的 JPEG/AX 标记对齐核对，图像为 1000×800，色块中心误差为0；2000×1100 窗口返回 IMAGE_TOO_LARGE，没有缩成1600继续。这一轮仅观察，不发送点击、按键或文本。

完整输入 fixture 尝试中途触发了 USER_PAUSED 接管保护并终止，没有自动解除暂停。因此本轮完整真实点击/关闭/文件选择链路未算通过；这些部分只报告已有 Rust/原生许可及 AppKit 对象回归结果，实际鼠标操作仍需用户确认。不能把之前 v0.1.7 的真实输入结果充当 v0.1.8 验收。

## 回退临时文件生命周期修复

实际只读回退验证发现：直接从临时PNG URL创建的CGImage可能继续懒加载；临时目录在返回后清理，后续JPEG编码竟得到仅156字节的头部，Finalize仍返回成功。新增“原图返回后删除PNG，再编码并重新解码JPEG”用例先RED，复现无有效图像尺寸；随后在同一回退函数中改为用内存持有完整PNG编码数据，再直接解码原尺寸图像，GREEN通过。没有新增截图服务、缩放或适配层。

修复后强制主后端失败，使用临时私有 helper 验证真实 screencapture 回退：两种1000×800窗口原点、三个色块的JPEG/AX对齐误差均为0，2000×1100原生截图明确拒绝；没有发送点击、按键或文本。故障注入仅在 `/tmp` 源码副本，不修改生产策略。SCK与回退的实际只读采集均通过，生命周期新增回归与原生153项smoke再次通过；独立复核已关闭该P2。
