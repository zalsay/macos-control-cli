# v0.1.2 原生操作提示（2026-10-19）

## 行为

输入前从其他应用或其他 Chrome 窗口恢复已授权窗口、且通过精确焦点校验后，在目标窗口主要覆盖的屏幕顶部居中显示“AI正在操作Chrome窗口...”。显示 3 秒后自动关闭，用户切换到其他应用时立即收起。提示由 Swift Helper 的非激活 NSPanel 承载，因此独立 CLI 与内置工具使用同一实现，不依赖 Electron 提示条或通知中心授权。

提示不会获取主窗口/键盘焦点，鼠标可穿透；同一前台窗口的连续输入不重复显示、不刷新计时。窗口再次失焦后被恢复时可再次提示。首次创建与布局不占用取消提交锁，展示前复核当前前台 PID 和 cancellation generation；窗口服务卡顿时仍沿用原有取消超时强杀兜底，此时尚未发送本次输入。提示仅在当前 cancellation generation 允许时显示；停止 Helper 后由系统销毁窗口。

CG/AX 的遮挡查询可能包含自身非交互浮层，所以输入点与提示重合时先收起提示，再执行原有完整遮挡、窗口身份、几何与最终焦点检查。没有忽略其他窗口或绕过输入安全校验。只读权限、列窗、连接、观察不会显示提示或切换前台。

## 验证

- 新增 `tests/toast-layout/main.swift`：7 项无窗口 BDD，覆盖主屏居中、菜单栏避让、跨屏面积选择、上方/负坐标副屏、窄屏、无屏和离屏情况；纳入默认 native-smoke。
- 新增显式 `bash tests/toast-smoke.sh`：直接验证 AppKit 窗口可见、前台不变、不能成为 key/main、鼠标穿透、重复显示只复用一个窗口、覆盖输入点时收起、取消后不展示、计时自动关闭。不截图、不发送输入。
- 原生 smoke：144 项 JSONL、3 项取消、6 项焦点和上述 7 项布局通过。
- 27 项 Rust 测试、fmt、严格 Clippy 通过；Swift arm64 / x86_64 macOS 14 target 严格无警告编译通过（本机 ARM 运行）。
- 版本锁、发布输入、归档准备与 Chrome 模块安装更新回归通过；Cargo、发布锁和归档元数据同步为 0.1.2。

通过现有受管安装流程安装本机 v0.1.2，并以私有 runtime 调用真实 CLI：

1. 将对照应用置于前台，依次调用 permissions/windows/connect/observe；前台不变且 Helper 没有可见提示窗口。
2. `press Cmd+L` 返回 `sent: true`，Chrome 成为前台；通过 CGWindowList 确认 Helper 原生提示窗口存在，标题精确匹配文案，逻辑尺寸 360 × 52。
3. 继续 `press Escape` 成功；仍复用原提示窗口，3 秒后自动消失，证明连续输入未刷新计时。
4. 再次切换对照应用并恢复 Chrome 后，提示再次出现；切离 Chrome 后立即收起，再次恢复后可展示；停止 daemon 后提示消失。

测试使用窗口元数据、前台状态与输入回执验证，没有查看或分析截图；observe 仅满足原生输入的 frame 契约。没有导航、登录、发布或点击网页业务按钮。私有 daemon、连接和截图目录均清理。

原生提示的实际视觉样式、屏幕顶部位置和全屏/真实多屏体验仍需用户在实际屏幕确认；不以自动化状态检查或截图代替用户验收。未发布 COS。
