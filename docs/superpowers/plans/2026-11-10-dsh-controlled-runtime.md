# Safarier 受控 DSH 运行时实施计划

目标：保留现有 CLI 的完整身份、清理与输入门禁，将 AGY 的 UI、隔离 DSH 和自动化权限说明集成到同一可交付版本。设计依据：`.build/dsh-control-integration-review/proposal.md`，用户已确认。

1. 核对当前源码、现有进程与 DSH/Node 依赖，记录并保护并行编辑。编译前后比较源码清单。
2. 构建侧生成版本化运行时和固定内容摘要；验证文件类型、摘要、权限、路径边界、符号链接和可信 Node；使用独立私有位置与原子安装，失败关闭。定义不可从待验证运行时自信任的校验根。
3. 把原 DshService 的查找和启动接入校验结果，保留其状态和数据隔离，生产路径不得回落至工作区或全局 DSH。校验替换竞态并记录实际保证范围。
4. 保留原 Manager/Runner 精确 bundle namespace、签名和身份检查，构建时同时记录运行时与应用身份；不能为 DSH 放宽现有控制门禁。
5. 定向测试合法运行时、篡改、越界链接、权限与替换、版本并存和失败关闭。主代理单独复核代码与用户变更；运行最小构建、签名、CLI 和 DSH 隔离验证。
6. 修订用户操作文档，明确打包、受控运行时安装、Node 与权限归属。构建可审阅候选后，再按现有用户授权与会话状态安排实际测试；不触碰在用进程、重置 TCC、使用全局输入或扩大权限。
