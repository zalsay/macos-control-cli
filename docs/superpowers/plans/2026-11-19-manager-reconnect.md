# Recover registered browsers after Manager restart

Keep the initial parent/child registration and the existing per-generation control protocol. Once the initial root was authenticated and its generation (if any) has drained, let that Runner accept a new authenticated root from a replacement Manager. The Runner must still hold its original profile lock. Never revive a session token, frame, or input request.

1. Add private per-Runner Unix rendezvous to the registration transport, keyed by workspace, profile and kernel process birth. Verify the exact named socket and audit-token-backed process/image identity before any reconnect control traffic. Keep unnamed socket verification unchanged for the original and per-generation channels.
2. Pass the authenticated replacement Manager identity from the root to the same generation server, and keep the controller's authenticated borrowed process binding distinct from a spawned child (no termination authority). Reuse root handshake, generation nonce, launch-spec validation, repository checks, exact target attachment and drain proof.
3. Route an existing locked profile to the reconnect path only when no original registration is available. Return the existing failure for old/unregistered Runner builds; do not fall back to launching over a live lock. Read launch arguments and time zone from the authenticated Runner for its existing repository binding, never its full environment.
4. On an explicit `connect`, let the surviving daemon bind to the verified replacement Manager after its pinned Manager exits. Retire old connection IDs, frames and pending semantic actions; never route them to the replacement.
5. Targeted verification: named socket credentials/pins, borrowed release with no child authority, no reconnect after unconfirmed drain, fresh session after the original root drops, existing open/release flow. Preserve the installed App and running browsers. Live Manager restart validation, if unavailable in an independent fixture, remains an explicit later acceptance step.
