## 1. 目标、边界与已有事实

### 目标

本地 Mac Agent 通过 mcc CLI 或文档化的 WSS 协议控制远端 Mac。Chrome、原像素截图、OCR、Jev、Apple Events、AX 和系统输入只在 Host 执行。本地仅解析参数、通信、维护私有会话凭据和接收图片；不是“本地完全零资源”。Host 仍需要当前用户的实际 macOS 桌面和原有三项授权，不提供 headless 桌面、虚拟显示器或无用户登录服务。

### 已有链路（必须复用）

- `src/main.rs::execute` 在本地配置分支后进行平台检查，普通请求调用 daemon；`click-target` 在启动 daemon 前读取 `Store::resolve_model`，`chrome-start` 应用 Host 布局/profile设置。
- `src/daemon.rs` 当前只监听私有 Unix socket，原 envelope 有 protocolVersion / scope / request；单个 Service 的 try_lock 冲突返回 BUSY，不排队。原 socket 权限不是公网认证，不能直接换监听地址后对外暴露。
- `src/service.rs` 持有一个 connection 和最多32帧；输入继续复用同帧坐标转换、窗口/PID/bundle/几何验证及 Swift 输入链。
- `observe` 当前返回 Host 的 `imagePath`；客户端不能把这个路径当作本地文件，也不能把原64KiB JSON控制消息限制直接放宽为无界图片载荷。
- `swift/Input.swift::cancel` 会结束 executionLease，并将 phase 改为 awaitingCountdown。因此“每次 WS 关闭就 disconnect/cancel，然后自动 connect”不是可用的断线恢复策略，会丢失暂停语义。
- `src/native.rs::Canceller::terminate` 是终止 helper 的清理路径，不是网络重连入口。当前 Jev 的取消 token 绑定 daemon stopping；不能为中止一个远端请求而停止他人 daemon。

### 首版范围

Host和官方CLI客户端验收均为macOS 14+；保留arm64/x64原有构建能力，不把未验收的Linux/Windows客户端列为完成。WS协议可供其他客户端后续实现，但不因此承诺跨平台二进制。

不新增：公网明文WS、反向隧道/NAT穿透、内置ACME、公网自动部署、多桌面隔离、shell执行接口、通用文件上传/下载、远程模型/Host管理配置API、远程解除暂停、远程请求TCC授权、自动接管他人连接。

## 2. 方案选择与关键决策

1. **选择内置 WSS**：mcc直接加载证书和私钥处理TLS；不强制新增反向代理/外部服务。反向代理部署可后续兼容，但不是首版依赖。
2. **选择应用私有 CA 信任**：无域名时使用IP SAN服务证书；客户端显式加载CA。无需购买证书、修改系统钥匙串，或提供 `--insecure`。
3. **选择单 Host 控制会话＋短命 RPC 连接**：正常CLI命令完成后的WS关闭不结束桌面lease；异常失联暂停原会话，不能通过新建helper或重放动作恢复。
4. **共享执行入口，不复制执行器**：提取现有CLI请求预处理及daemon分发供本地和Host复用；WSS只负责认证、校验、会话、边界控制和图片传输。
5. **必要的扩展必须在原取消/暂停机制内完成**：为网络失联增加保持lease/paused的受控入口及每请求取消上下文，不另起第二套“远端点击器”或绕开原Service。

## 3. 新增 CLI（原始设计，已于2026-10-28接入）

### Host 本地初始化

```sh
mcc host tls init --ip <公网IP> --output-dir /secure/mcc-tls
mcc host token init --output /secure/mcc-host.token

mcc host start \
  --listen 0.0.0.0:8765 \
  --tls-cert /secure/mcc-tls/host-cert.pem \
  --tls-key /secure/mcc-tls/host-key.pem \
  --token-file /secure/mcc-host.token
```

- `tls init`可重复指定 `--ip` 或 `--dns`，合计最多8个明确SAN；不向公网查询/猜测本机地址。未指定有效SAN则失败。IPv4/IPv6按IP解析，域名作为DNS SAN，不以CN代替SAN。
- 初始化生成 `host-ca.pem`、`host-ca-key.pem`、`host-cert.pem`、`host-key.pem`。客户端只拿CA公共证书，CA签发私钥和服务私钥不外传。
- 初始有效期：CA365天、叶证书90天；生成结果回执明确显示到期时间和CA DER的SHA-256指纹，不输出私钥或token。首版不自动续期；到期前在新目录重新生成并可信重新配对，不悄悄覆盖原CA。
- CA签发私钥仅供本地证书管理，可由操作者离线保存；运行Host只需要服务证书/服务私钥和独立token。
- token由系统安全随机源产生至少256bit随机性；不要求用户手打弱口令，不从Jev API key或.env派生。不输出token内容，只回执文件路径和创建状态。
- 初始化目录0700，私钥/token文件0600、当前用户所有，拒绝符号链接、错误所有者、非普通文件、已有目标和部分覆盖。复用原私有文件与原子发布原语；失败清理自己创建的临时资源。
- `host start`首版为前台常驻进程，便于日志和信号管理；不暗中安装launchd、不自行启用远程登录或开放防火墙。
- 默认listen为127.0.0.1:8765，公网需显式指定bind。任何地址都必须WSS+token；证书或token无效时必须在监听前失败。
- 首版Host生命周期命令只从Host本地执行。正常停止后无监听、无残留WS线程或本进程持有的输入；不关闭Chrome、不停止未持有的daemon。

### Agent 调用

通过已核验SSH/可信离线渠道取得 `host-ca.pem` 和客户端token，独立核对CA指纹；不从首次不可信连接下载CA后自动信任。

```sh
mcc --remote wss://<公网IP>:8765/mcc/v1 \
  --ca-cert /secure/host-ca.pem \
  --token-file /secure/mcc-host.token \
  chrome start --profile mcc

mcc --remote wss://<公网IP>:8765/mcc/v1 \
  --ca-cert /secure/host-ca.pem \
  --token-file /secure/mcc-host.token \
  click-target --connection <id> --target 保存
```

- remote路由先于本地Runtime/daemon/Swift初始化及模型读取。缺失本地models.toml、本机未获AX/屏幕录制授权，不阻止远端调用；网络/认证/Host错误绝不回退成本地操作。
- `--remote`必须是显式WSS URL；拒绝userinfo、query、fragment、不支持的路径及无效主机/端口。不在URL或argv提供token内容；只接受有界、私有、当前用户普通token文件。
- 首版每次明确指定remote/CA/token文件，不增加隐式全局远端默认值，不因某个配置存在就改变原命令的本地目标。
- 不改原models.toml格式；客户端会话缓存使用现有私有配置存储原语，在MCC_CONFIG_DIR下保存。不读取Host私钥、Jev凭据或本地.env。
- `mcc`/`desktop-control`保留desktop scope，`copis-chrome`保留chrome scope；Host启动入口固定scope，握手必须匹配，不静默提升权限。
- `--help`、`--version`仍可本地只读；remote下禁止发送 `--config`、`--jev-key`、daemon生命周期和host生命周期操作。

## 4. TLS 与公网入口

- 使用成熟TLS/WebSocket/X.509库，不手写密码协议。候选为rustls、tungstenite、rcgen；具体版本/feature在实现前按Rust 1.89 MSRV、维护状态、已知安全问题和最小依赖锁定，不在本规格声称未验证的版本兼容。
- TLS仅接受1.2/1.3并使用库的安全默认套件，验证服务证书链、有效期与URL中的DNS/IP身份。默认系统根可用于现有受信任证书；`--ca-cert`是该remote连接的显式私有根，不改变系统信任或Jev curl的信任配置。
- 不提供跳过验证/过期放行/明文降级；拒绝无TLS的HTTP/WS、重定向到另一目标和自动代理环境变量继承。IP/SAN变化须重新签发或配对，不能忽略证书错误。
- 握手使用 `Authorization: Bearer <token>`；常量时间比较，不记录凭据、签名私钥或完整认证头。认证成功之前不启动daemon/Chrome、不读模型key、不发送窗口列表/图片。
- 固定 `GET /mcc/v1`，WS子协议 `mcc.remote.v1`。非浏览器CLI无Origin可接受；带Origin的浏览器请求首版全部拒绝，不能凭带Cookie的浏览器跨站接入。没有HTTP静态文件或管理目录服务。
- 证书与token只在Host启动时读取。首版轮换需由Host本地按暂停/停止流程完成，再换文件/重启并重新建立会话；不宣称文件更新会立即热生效。重启不能自动绕过旧暂停/失联锁。
- Host token等同该Host范围内桌面控制凭据；这不是针对不可信Agent的macOS沙箱。动作白名单/文件API边界不能防止已授权桌面操作本身读取页面或通过UI进行其他操作。

### 初始资源上限

| 项目 | 初始限制 |
|---|---|
| TCP/TLS/WS未认证连接 | 合计最多8，握手总期限5秒 |
| 已认证WS连接 | 最多4，一个控制会话/一个进行中的动作 |
| 认证失败 | 按来源IP限速，另有全局预算，不为每个随机IP无界建表 |
| 普通命令 | 每会话每秒10条、突发20；超限拒绝，不积压输入 |
| 控制JSON/握手头 | 各最多64KiB/8KiB；先检查再解析 |
| WS压缩 | 禁用；对分片累计体积和数量设上限 |
| 图片 | 仍为JPEG<1MiB；二进制分块，每块<=64KiB |
| 活跃请求心跳 | 每5秒探测，最多15秒无响应进入失联流程 |
| 常规RPC期限 | 与现有55秒客户端/45秒helper上限协调，传输总期限不无界扩展 |
| 控制会话空闲期限 | 300秒；到期暂停并失效，不静默交给另一客户端 |
| 请求结果缓存 | 最多64项/会话；以单调序号高水位防止缓存淘汰后重复执行 |

限速与资源表均须有界清理。以上是可测试的首版默认值，不是抗任意公网DDoS承诺；公网部署仍需要操作者配置网络入口访问策略。

## 5. 传输协议与动作白名单

外层独立remote协议，内层仍走原版本/scope校验与请求处理。握手报告remote protocol、mcc版本、scope、Host启动标识和能力；首版客户端/Host要求mcc精确版本匹配，原daemon动态Decisions与原生能力门禁保留。

拟定RPC信封（会话字段为敏感凭据，不进入Debug/日志）：

```json
{
  "remoteProtocol": 1,
  "id": "random-request-id",
  "session": "private-session-id",
  "sequence": 1,
  "scope": "desktop",
  "request": {"action": "windows"}
}
```

- 认证/版本/结构/未知字段/大小/动作权限/会话归属/序号均在副作用前验证；RPC结果保留原ok/protocolVersion/scope与结构化错误语义。
- 允许：status、apps（desktop）、windows、permissions只读、chrome-start、connect、observe、click、click-target、scroll、type、press、disconnect，以及受限的frame传输与会话状态查询。
- `select-file`保留远端路径语义，但仅在Host本地显式配置允许根目录后开放，缺省拒绝；复用原选文件路径验证，另校验解析后路径位于允许根内，禁止符号链接逃逸。不新增客户端自动上传。
- 远端禁止：daemon_stop、所有daemon/Host生命周期、模型或Host配置写入、permissions --request、恢复暂停、任意文件路径读取/下载，以及客户端注入jevKey/jevUrl/jevModel/jevProtocol/profileMarkerPath等内部字段。
- 模型URL/key/model、enabled、窗口布局默认值及Chrome默认profile均由共享执行入口在Host读取；click-target只收目标与连接ID，继续原target＋候选ID/文字请求，不发送图片/坐标给Jev。
- 同一请求ID/序号只执行一次。已完成的重复请求可返回缓存回执；过期、已淘汰或状态不确定的请求明确拒绝，不当作新输入。客户端不自动重发改变桌面状态的动作。
- `click_sent` / `sent:true`仍不代表业务完成，`effectVerified:false`不变。传输结果丢失时返回结果不确定及原requestId，不能伪报未执行或已完成。

## 6. 会话所有权、短命CLI与失联状态机

### 凭据与归属

TLS验证与Host token认证后才能创建控制会话。Host生成独立高熵会话凭据；客户端用现有私有存储/写锁保存至endpoint、scope、CA身份、Host启动标识绑定的本地会话文件，不把凭据放命令行。客户端并发执行同一会话的命令返回BUSY，不自动排队。

connectionId、frameId及执行结果归属于控制会话。仅知道另一连接ID或frameId不足以操作/取图；同一token下另一会话也不能接管。Host中已存在非本会话连接则拒绝，不自行disconnect、结束daemon或新建helper。

认证/只读请求可以建立会话记录，但只有chrome-start/connect等取得控制权的操作才占用控制会话；未持有桌面连接、没有进行中或结果不确定动作的只读会话失效，不应把整个Host锁进暂停。

正常动作完成并传输完图片后，客户端发送带相同id/sequence的完成确认，然后正常关闭WS。此关闭仅释放RPC网络连接，桌面连接和控制条lease保留，下一条独立CLI可以继续使用。完成确认丢失按异常处理，宁可保守暂停，不推断客户端一定收到成功。

### 状态

`idle -> owned -> running -> owned`；异常失联/空闲到期为 `lost/paused`；取消未确认进入 `cancel_unconfirmed`；Host身份/版本/证书改变或无法核对旧归属进入 `recovery_required`。

- 只有活动请求完成确认后的正常WS关闭不触发暂停；不得把每次CLI退出当disconnect，也不得把异常Close码伪装成已完成确认。
- 活动操作中TCP断开、心跳超时、传输超时、结果发送失败或无完成确认，先封闭本会话的新输入，再取消本请求模型/原生动作并保持原executionLease的暂停状态；旧请求不能在迟到结果后继续点击。
- 失联检测有明确时限，不承诺网络断掉的瞬间就能感知。只有取消/暂停ACK确认后才承诺该请求不会继续投递；无法确认则保持 `CANCEL_UNCONFIRMED` / 禁止新输入，不显示“已安全停止”。
- 网络失联入口复用原InputCancellation锁、input epoch、held-key释放和控制条。不能调用会重置phase的旧cancel后自动connect，不能替换helper/原生执行器或自动清除USER_PAUSED。
- 原Jev取消机制扩展为受Host所有权约束的每请求取消，不能把单会话失联映射为全局daemon_stop。取消/保持暂停必须在Service主动作锁被占用时仍可执行，不能作为普通排队RPC等待当前模型/输入结束；原daemon侧先核对活动请求及所有权，再使用原取消原语的受控侧带，内部取消能力不暴露给WS客户端。在观察、Jev等待、倒计时、鼠标移动/按键和图片传输等阶段均要做竞态测试。
- 恢复连接后只允许认证、状态、取已完成回执、必要只读观察；输入恢复需要远端本人通过原控制条继续，并等待原3秒倒计时，同时以新请求序号发起动作。没有可恢复控制条/lease时，要求Host本地显式恢复处理，远端不能自行“修复”。
- 用户主动disconnect仍走原显式释放路径，但失联锁/USER_PAUSED不因remote disconnect或重新建会话被自动清掉。处于暂停或恢复要求时，不能靠“disconnect再connect”建立可输入新lease。
- Host启动/重启、token轮换、服务异常退出后，旧远端凭据不能被默默当新会话继续；保留可核对的所有权/恢复记录。不能证明先前停止状态或原归属时保守拒绝，由Host本地本人处理，不杀他人进程。
- helper不能确认停止时，终止自己持有的helper只可作为末级安全清理，并进入recovery_required；不自动重启或把“新helper未暂停”当恢复。不能终止他人helper。
- Host正常停止、socket异常和信号退出只处理本进程可证明持有的会话/动作。Host是借用原daemon时不能随意停止它；自己创建的执行资源也不得以“重启后清零暂停”作为恢复策略。

本规格的单控制会话仅指本Host，并不承诺隔离同一Mac上的所有其他独立mcc进程；远端Mac的物理桌面仍会被占用，本地人工接管应触发原暂停。

## 7. 截图与路径边界

- `observe`结果由Host从该会话注册帧取得图片，先返回图片manifest（requestId、frameId、MIME、总字节数和SHA-256），再在同一WSS请求上传输有界二进制块。固定顺序/一个进行中请求，不用无界base64塞回控制JSON。
- 客户端验证manifest归属、总长度与摘要，以原create_new/0600规则保存本地图片；返回的imagePath必须是实际本地文件。`--output`只在客户端解释，绝不让Host处理客户端文件路径。
- 下载中断/超限/摘要不符时不返回可用图片，清理自己创建的半文件；不覆盖原文件，不在元数据缺失时猜测宽高或缩图。
- Host只按自己的connection/frame登记读取图片；不接受客户端传入Host任意路径。打开时核对私有帧目录、普通文件、所有者和符号链接，防止帧清理/替换期间竞态。最多32帧和原disconnect清理规则不变。
- click-target内部观察图片继续留在Host；正常只回原选择/坐标/投递回执，不因为增加WS就默认把内部截图传回客户端，也不增加OCR复核。

## 9. 验收矩阵（实施计划据此拆分）

1. **证书与token**：IP/DNS SAN正确；链/域名/IP/到期/错误CA/错私钥/弱或过大token拒绝；权限/所有权/符号链接/FIFO/已有文件/原子失败；私钥、token不进stdout、Debug、日志、包或测试夹具。
2. **认证先于副作用**：无token/错token/明文/超时/错误path或Origin/协议或scope不匹配/超大或碎片消息，无daemon/helper/Chrome/模型调用；日志脱敏，限速表有界。
3. **客户端不执行本地操作**：本地无模型配置、故意设置不可用helper和独立runtime，远端调用仍成功且本地runtime未创建；远端失败不落回本地。
4. **共享模型配置**：Host配置Jev，远端启用时走loopback Decisions与原点击；Host禁用时在观察/请求/输入前返回MODEL_DISABLED；客户端不能注入URL/key或绕过。
5. **所有权与重复请求**：两个客户端/同token不同session/错误conn或frame/并行CLI/过期序号、缓存淘汰、Host重启等均不能接管或重放；本地既有连接不被替换。
6. **连续短命CLI**：start/connect ->正常确认关闭->observe ->正常确认关闭->click，跨进程复用同一连接/帧/原lease；不是把每次调用当新helper。
7. **断线竞态**：观察、模型等待、倒计时、移动、键按下、动作已投递但回执丢失、ACK丢失、图传期间断线；取消ACK后无迟到输入；不确定时不伪报成功；无自动重试。
8. **暂停保持**：USER_PAUSED、正常接管、Host停止/异常/重启、token轮换、idle过期、disconnect/reconnect、scope切换都不得绕过暂停；本地本人继续仍须3秒；无控制条时需要本地恢复。
9. **图片与文件**：原像素1x/2x、宽<=1600/高<=8192/JPEG<1MiB；有界分块、本地路径、output冲突、损坏/中断清理、frame归属/符号链接/竞态；远端select-file默认拒绝及允许根验证；内部语义点击无额外图传/OCR复核。
10. **原功能回归**：现有Rust、native BDD/186项协议检查、Chrome profile、文件对话框、权限、焦点/窗口/暂停/输入、Decisions压缩及旧本地CLI形状继续通过。
11. **分发与安装**：Host/client库均随独立包分发；证书/token/.env/运行帧不入包；包源码一致性、SHA256、临时HOME/prefix安装升级通过，实际旧安装/配置/标签不动。
12. **分层实测**：先本机TLS loopback+fake native/Decisions与可复现断线；再两台Mac的真实WSS/CA信任、Host桌面操作及原门禁，最后受控公网连接。模拟测试不冒充双机/公网验收；没有第二台Mac/可控公网地址时明确标未验收，不宣称上线完成。

任何未确认取消、暂停绕过、凭据泄漏、明文降级、跨会话取图/输入或真实GUI红测都是阻塞项，不能靠关闭校验/放宽限制/自动重启来交付。
