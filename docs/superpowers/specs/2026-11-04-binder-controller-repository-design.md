# Binder controller repository lifetime — proposed design

**Status: DRAFT; human approval of this exact architecture is required before any implementation or test code.** Main agent owns design/code review. The 12 rulings in `.build/automation-binder-controller-design-20261104/main-review/main-source-trace-and-rulings.md` are incorporated below as the proposed architecture, pending human approval. This unit is documentation only, not formal Binder wiring. No current build, runtime or test validation is claimed. The historical 112 runtime calls and 2998 manifest entries are prior evidence only. Baseline is `.build/automation-binder-writequeue-impl-20261104/worker/attempt-017/src/` (017); original production client is `Sources/SafarierCore/AutomationRunnerClient.swift`. Snapshot C at baseline 017 is unchanged by this unit.

## Source observations and alternatives

* 017 `RepositoryBindingProvider.makeFixture` parses original `RunnerLaunchSpec` arguments/environment and pins root/workspace/locks; `read(deadline:)` establishes then compares the entire repository observation. Only `.runner` acquires `ProfileLock`; `.controller` does not. Its fixture executable path constraints are not a production-composition API.
* 017 `V1KernelFixture.swift:51` directly uses `FoundationProcessSpawner().spawnOwned(..., arguments: spec.arguments(), environment: env, standardInput: pair.child)` to obtain `OwnedRunnerProcess`; it does not run `RunnerLauncher`. `RunnerLauncher` is production-path reference only, not run or stubbed in this fixture. The fixture parent retains actual `KernelIdentityBridge`, `OwnedRunnerProcess`, initial `BIProcess` birth identity, inspector and channel; checks fresh child metadata and actual peer, but has no retained controller repository binding. It uses original launch spec/args/environment. Cleanup waits and only requests termination through that owner after fresh matching birth metadata; it can report unconfirmed cleanup.
* 017 `FixtureWriterBinding` is minted file-private in `AutomationRunnerServer.swift`, weakly refers to that server, holds channel/reader/context; its admissions are `ready`, `response(UUID)`, `diagnostic`. The channel stores a weak binding, associates its reader lease, and dispatches validation by calling the server at the same write-queue head and each partial/EINTR retry; `physicalWriteAttempt` uses the existing revocation check and actual single write. It cannot represent a controller by inserting a `nil` server or calling provider only before enqueue.
* 017 `AutomationChannel.sendBound` (264–273) closes the channel on **any** `reserveBound` error. In contrast, original legacy `sendImpl` reservation failure leaves an otherwise open channel open, and actual `AutomationRunnerClient.sendRequest` (152–172) specially catches `sendBackpressure`, removes the sent ID and finishes that pending generation with `sessionBusy` and `definitelyUnsent: true`. The controller cannot directly inherit the runner close-on-backpressure branch.
* Real `AutomationRunnerClient.start` calls `workspace.launchOwnedBackground`, negotiates with `AutomationHandshakeCodec.negotiate` (which uses public `send`/`receive`), constructs the client only after ready provides `runnerInstanceID`, then starts a detached reader also using public `receive`. The client already owns pending/generation, cancellation flag, caller deadline, 4096 sent-ID tombstones, two control reservations, pump and failure semantics. This design changes its seams, not its correlation engine. `SafarierWorkspace`/`RunnerLauncher` and `RunnerLaunchSpec` remain authoritative real launch path; the fixture is not a permissive replacement workspace.

Alternatives: (1) `provider.read` immediately before legacy send is small but rejected: queued delay/retry and inbound commit remain unbound. (2) Independent controller socket writer/reader/client is rejected: duplicate physical writer, lease race and loss of real correlation/timeout semantics. (3) **Preferred:** retain a concrete bootstrap-to-client controller context and add a closed role to the *existing* 017 capability/queue, using the actual client. This changes the least authoritative path, but requires explicit decisions below and approval before implementation.

## Proposed closed ownership and interfaces

Names below are proposed fixture-copy internal interfaces, not existing APIs. Deterministically extract/factor only the real startup workspace/launcher entry from a copy of the actual 236-line client: retain its actor implementation, pending/outbound queue, timers, reservation counts, sent IDs, action validation, original failure mapping and reader loop. Record the source hash and exact retained/extracted ranges before future execution. Do not copy the entire real Core, construct an artificial request loop, load a real workspace or add a permissive production startup stub. Production source/dependency refactor remains separately blocked.

* Create exactly one concrete `ControllerGenerationContext` **before launch**, retaining the existing actual self/bundle bridge, original fixed lifetime, original spec/args/environment, a single `RepositoryBindingProvider.makeFixture(role: .controller, ...)` and its initial whole-document observation, channel, nonreading inspector and original claimed reader lease. Keep the same provider and observation until this generation closes; never release/recreate and silently rebaseline. Its prelaunch state cannot contain an owner yet: `attachOwnedChildOnce(_ owner: OwnedRunnerProcess, birth: BIProcess)` transitions exactly once after the original owned spawn and fresh birth capture. No user-provided, wire or scanned PID serves as ownership.
* The context itself is the bootstrap owner until valid ready and actual peer pin. Then construct the **actual client** using `ready.runnerInstanceID`, and `attachClientOnce(_ client: AutomationRunnerClient)` attaches exactly that client; no requests until transfer is complete. Client strongly retains the context; context holds a weak client reference; no replacement client or ownership cycle. This is local ownership, not a new handshake/state protocol. The startup stack retains the context through each await.
* Generalize the existing `FixtureWriterBinding` to a closed concrete owner enum: runner weak reference or controller context weak reference, with generation and channel/lease identity. Missing/deallocated owner, wrong role, wrong lease or generation fails closed; there is no nil-to-legacy fallback. Fix the lexical location to the **fixture-derived `AutomationRunnerServer.swift` file**: keep `FixtureWriterBinding`, `SealedWriteAdmission`, their `fileprivate` initializers and the existing server factory there, and declare the concrete `ControllerGenerationContext` and its controller factory in that same file. Both concrete owner implementations therefore have legal Swift `fileprivate` access without widening constructors. Other files may use module-internal read-only identity facts and call concrete owner operations, but cannot invoke these initializers or mint an admission directly; no public constructor or generic authority is introduced. Only a real concrete owner mints its own role. Channel retains binding weakly; each live owner retains its own binding strongly. Foreign admission rejection closes the receiving channel only, without claiming, consuming or revoking the original foreign owner. Admissions remain one-shot.
* Extend the closed admission kinds with `controllerHello` and `controllerRequest(UUID, generation: UUID)`, retaining runner `ready`/`response`/`diagnostic`. A private owner factory mints only the original canonical `makeChallenge` output for the expected profile and freshly generated nonce, once, or the encoded request owned by the attached real client with its exact pending ID/generation. There is no caller-selected role/unchecked UUID, callback, protocol, Boolean authorizer, parallel writer, collector or new transport. The original queue, byte budget, head/job receipt, physical-write machinery and single `Darwin.write` are shared; dispatch validation directly to the concrete runner server or controller context.
* Proposed fixture-internal `negotiateBound(context: ControllerGenerationContext, startupCutoff: UInt64) async throws -> AutomationHandshakeResponse` uses the existing codec and the already-claimed `AutomationChannel.ReaderLease`. On completed ready+peer verification transfer the **same** lease once to the actual client's existing reader loop, using `lease.receive()` there as well. Bootstrap stops reading before handoff; there is no second reader, watcher, public `receive` alias or reader in the inspector. Failed transfer revokes and closes.
* Each generation uses its existing single first-terminal record for stop/failure arbitration. Synchronous stop first revokes terminal/channel authority and ensures pending continuations settle at most once; outstanding concrete checks hold resources alive until safely drained or excluded before provider/inspector release. No universal orphan or quiescence guarantee is implied.

## State and verification ordering

1. Before launch, construct the one controller generation/context, validate self/resources and exact trusted fixture spec/args/environment and establish the provider's whole-document observation. Claim the single reader lease and retain channel/inspector. Revalidate the **same** baseline immediately before spawn admission. No controller lock acquisition or PID-file claim. If changed before admission, deny without spawning; a mutation during `Process.run` cannot retroactively prevent that launch and requires owner-only cleanup. After spawn attach the original owner and fresh actual birth once, then re-read the same baseline.
2. Install controller binding before first write. At queue head and every retry for the single canonical manager hello check baseline, self/resources and original owned child against fresh birth, original startup cutoff and revocation. This exact one-shot hello is the sole pre-peer wire frame: peer last-use may be unavailable before hello. No generic `allowUnpinned`, request or capabilities before ready and pin.
3. Read ready through the lease and parse original nonce/profile/PID/instance. Check actual peer through the nonreading inspector against the retained owned child, fresh birth, self/resources and same provider baseline. Recheck after awaits within the startup cutoff. Only then attach the actual client once and transfer the same lease; ready is correlation, not an identity or GUI grant.
4. Outbound actual `sendRequest` retains original pending identity, cancellation flag, request cutoff, reservations, sent-ID decisions and queue. Check the real pending/generation/cancel/deadline/attempt state before and after each relevant await and queue admission. Seal only its exact encoded request; queue validation at head and every retry checks ready, same pending ownership, baseline, self/resources, fresh owned birth and pinned actual peer. Return-to-queue and immediately pre-write checks verify job receipt, revocation and fixed cutoff. Channel/auth failure revokes the generation. No new physical writer.
5. After `lease.receive()` returns, the existing client decodes and correlates schema, ID and action; capture only ID and generation, not a `Pending` value to commit later. Change the copied actual receive method to async; before and after **each** await, and immediately before remove/resume, relookup the same live `pending[id]`, verify exact generation/action, cancellation flag, original deadline and closed/terminal state, and repeat after full context check. Check repository, bridge, original owner/birth and pinned actual peer before commit. Unknown, malformed, foreign, stale, cancelled and late replies cannot revive a request or resume twice; retain original failure/side-effects classification and tombstones.

## Bound reservation backpressure — explicit role-specific proposal

017 `sendBound` performs ownership validation, one-shot `claim()`, frame validation and `reserveBound` before enqueue, but its catch currently calls `close()` for every reservation failure. Change the existing bound send path, not the writer or byte budget, with this closed-role-specific handling:

1. Check the exact live binding/channel/reader/generation and claim the admission once. Invalid ownership, foreign admission, already-claimed/settled admission, closed channel, invalid frame or other identity/structural error remains terminal for the **receiving** generation. A foreign rejection does not claim, consume, or revoke the original foreign owner. No role fallback.
2. After valid controller ownership and claim, if and only if `reserveBound` reports byte-budget `sendBackpressure` while the channel/generation remain live and **before any enqueue or physical write for this admission**, settle that one admission and its deadline/timer exactly once, release any reservation only if actually acquired, and return the same `AutomationChannel.ChannelError.sendBackpressure` without closing/revoking the healthy generation. No byte budget leak, queued job, physical write, retry or replay is permitted for that admission. If terminal state races with this branch, terminal state wins and it is not reported as healthy backpressure.
3. The unchanged real client catch checks that the same pending generation still exists; only then it removes its sent ID and finishes that request with `sessionBusy`, `definitelyUnsent: true`. If cancellation/timeout already removed that pending generation, preserve the original catch's guard rather than resuming again or altering tombstones out of turn. This explicit original exception does not move the attempted transition: it remains `sentIDs.insert` and `pending[id].attempted = true` before `await channel.send`, not first physical byte.
4. For a **runner** admission retain 017 exactly: reservation errors, including backpressure, close/fail according to the original runner-bound path. All other controller reservation/identity/closed/foreign errors remain terminal as above. After successful reservation, original same queue/head/receipt and single physical writer remain in use for both roles.

This role split is a proposed change to the existing fixture-derived channel, not implemented or validated. Authorization awaits human approval of the complete design.

## Attempt boundary and fixed budgets — proposed exact policy

The existing real `sendRequest` first checks cancellation/deadline and sent-ID limits, inserts the sent ID and sets `pending[id].attempted = true` **before** awaiting `channel.send`; backpressure is its original explicitly definitely-unsent exception. Preserve that actor-isolated transition, not a newly invented first-physical-byte boundary. Before the transition, the original per-request timeout/cancel timer removes and completes only that request, and an unused sealed admission may be invalidated without closing a healthy client. Once attempted, including time waiting at the channel queue and any partial write, timeout/cancel follows the original `failTimedRequest` connection-close path and mutating actions retain possible/indeterminate side effects. Keep original backpressure handling and sent-ID reversal exactly as the original; channel or authentication failure revokes the generation. Never silently upgrade attempted work to definitely-unsent after a later check.

The request's original absolute caller deadline is fixed at registration **before** outbound wait and remains authoritative. Arm controller writer timing only at the existing attempted/send transition, with the already-captured absolute deadline, not `now + timeout`; do not arm runner's binding-wide timer while the client still treats the request as unattempted. Each controller check derives a sealed fixed expiry of `min(original request cutoff, fixed fixture lifetime expiry)` (or `min(original startup cutoff, fixed fixture lifetime expiry)` for startup); an already expired budget fails, never renews. Do **not** silently impose `FrameDeadline`'s default 3-second frame ceiling on a longer caller timeout or restart that 3 seconds after an await. Implement a private owner-derived fixed-expiry extension if needed, while preserving runner 017 `FrameDeadline` 3-second/45-second defaults and the bridge/C remaining-duration conversion unchanged. The independent 45-second offline fixture lifetime remains an explicitly stated outer limit; a longer caller timeout therefore can be cut short by fixture lifetime, which is not a claim of production timeout equivalence. No production timeout policy change is approved by this design.

## Fixture seam and limits

The recommended deterministic seam is a **fixture copy** of the original actual client, with only its real workspace/launcher-dependent startup entry factored out. The offline fixture prepares the one context/provider/lease before launch, reuses the actual 017 `FoundationProcessSpawner().spawnOwned(...)` and returned `OwnedRunnerProcess`, with `spec.arguments()`, original environment and `pair.child` as standard input, attaches original owner and birth once, then invokes the copied real client's common bootstrap/handshake path and constructs the original actor core. The production `RunnerLauncher` is a source reference only and is neither run nor stubbed. No real `SafarierWorkspace`, LA, Keychain, app or permissive dummy workspace is loaded or stubbed, and no new production startup stub is introduced. Preserve a mapping of source hash and source ranges for every retained/factored section. This seam proves only the offline copy; original production composition is not refactored, exercised or enabled. If deterministic extraction cannot preserve those exact behaviors without a new production stub or parallel client, stop and obtain human approval for a revised design rather than filling the gap with a substitute.

OS process/peer and filesystem observations are not atomic with writes/reads or each other; whole-document checks cannot prevent transient mutate-and-restore between checks or hostile same-UID interference. Identity checks and safe shutdown narrow races, do not establish kernel/FS transactional quiescence. Never infer exclusive child lock from lock-file contents/PID. Cleanup retains original owner: close/revoke, await termination, and only if owner still running and fresh child birth matches original request termination through that owner; otherwise `cleanup_unconfirmed`. No process scan or wire-provided kill authority.

## Planned independent controller evidence and acceptance boundary

Future tests must isolate controller enforcement. For inbound, let the runner complete its own checks and emit a valid reply, then go idle; pause the controller after it reads/correlates that valid reply and before its context check/commit, mutate actual C's shared repository, and require controller rejection without a successful continuation. This prevents a runner-side rejection from masquerading as a controller check. For outbound head/retry, use scheduling-only instrumentation and demonstrate controller context itself rejects actual C mutation at its own queue boundary; zero bytes because runner rejected is not evidence of that check. Preserve runner 017 regressions separately.

Exercise actual C mutations before launch admission, during launch, at queue head, after partial write/retry, and after a valid reply; original-client cancel/timeout before and after attempted, post-await same-generation relookup, foreign owner/lease/admission without harming the original foreign owner, source path/birth/resources, byte/inode/mode/unselected-record changes, controller byte-reservation backpressure and healthy-generation follow-up, unchanged runner close-on-backpressure, sent-ID limit, no replay, cleanup and ASan. Actual OS EINTR injection, production composition and real GUI/input remain distinct unverified gates. No test or runtime has been run in this design unit. Future compile/API absence or compile-negative results are structural evidence only, never runtime RED. A behavioral RED requires an observed violation of the target oracle on a compilable original actual path or future human-approved isolated copy; scheduling hooks may control timing but must not fabricate authorization/validation results. If no lawful behavioral RED can be obtained, record it as unverifiable rather than bypassing the constraint.
