# Binder write-queue boundary: concrete proposed design

**Status: proposed, pending human approval; not implementation authorization.** Terra authors; main alone conducts design/code review. This draft incorporates main's proposed source-trace rulings in `.build/automation-binder-writequeue-design-20261104/main-review/main-source-trace-and-rulings.md` and source hashes in `main-read-source-SHA256.json`. Neither these rulings nor this draft are runtime proof. A new exact execution contract and explicit human approval are required before source changes, builds or tests.

## Base, scope and observed gap

Actual offline base is `.build/automation-binder-v1-context-20261104/worker/attempt-014/src/`, especially `AutomationChannel`, `AutomationRunnerServer`, `AutomationHandshake`, `FrameDeadline`, `RepositoryBindingProvider`, `KernelIdentityBridge` and `ProfileLock`; product source is reference only, not promotion. Main's trace identifies `sendImpl` as reserving before dispatch to the existing serial `writeQueue`, which currently checks expiry, not full context, at dequeue and inside its synchronous `Darwin.write` loop. Server-side write-before checks can precede a queue wait. Ready uses public `channel.send`; malformed diagnostics and scheduled responses use the existing writer too. The prior final audit explicitly says actual serial dequeue full revalidation was false. Historical 74 calls are prior-stage evidence only.

Keep the 4-byte big-endian prefix, nonempty frame <= 65,536 bytes, pending wire-byte budget `4 * (65_536 + 4)` bytes (not a four-job cap; small frames can occupy more than four jobs), single original channel, exclusive original reader lease, server phases/one-shot tokens, request loop, handler and unavailable-only filter. The retained real context includes actual C identity bridge, actual parent/peer pins, same repository provider, original profile lock and lifetime. No fake authentication, new verifier/C source, transport, reader, collector or production/GUI composition.

## Alternatives and proposed selection

1. **Selected for human consideration:** extend the SAME original `writeQueue` with one queue-owned head, held across async concrete checks; progress the SAME original `Darwin.write` one attempt at a time. Async check completion returns to that same queue; only head advances. This is a change to the existing engine, not a second engine.
2. Replace writer with an actor: actor reentrancy still requires explicit FIFO head management; it replaces the established queue/writer and is broader. Rejected.
3. Check only before enqueue or only at head: pre-enqueue misses queue mutations; head-only misses mutations before subsequent short-write/EINTR retries. Rejected for this proposal. No semaphore, dispatch.sync, thread parking, queue suspension, lock across await, new nonblocking mode/poller or independent writer.

## Foreign object and one-shot ordering

For `installFixtureWriter` and `sendBound`, first verify **receiving-channel structural ownership** against immutable binding/lease/channel identities, before touching a foreign admission's one-shot state or foreign revocation. Do not hold the channel lock while taking another object's lock or invoke actor/C/owner callbacks under it. If receiving channel G sees a binding, lease or admission owned by F, reject and close **only G**; if G has a local binding terminalize G's own state only. Do not consume the foreign admission or lease, revoke/close F or modify F's context. F must retain the ability to submit that admission once and complete full original checks.

After structural ownership is established, claim the admission once using only its local bookkeeping; this is not an authentication check and uses no C/actor callback. Then recheck receiver open/binding state when reserving. A failed attempt after claim is never rolled back into reusable authority. A duplicate/consumed admission is denied and its own receiving channel closes; no duplicate frame. Synchronize these steps without holding a channel lock across another object's lock, preserving close races and exactly-once settlement.

## FIFO job state and lifecycle

Reserve header + payload against the existing pending budget; preserve bounded acceptance and wire framing. FIFO means **original queue-admission order**, not order in which concurrent callers started or separately reserved. Append callbacks to the same queue; one head at a time advances through `validating -> attempting -> validating` on retry, then terminal. While head validation awaits, the queue itself remains free for append/terminal housekeeping but must not start any later head.

At head and before **every later physical attempt** after a short write or EINTR, start a one-shot unstructured task owned by that head which re-enters the **original actual server actor** through proposed `validateOwnedQueuedWrite(_ admission:)`. A missing weak server denies. Before and after awaiting the SAME original `fixtureCheck`, the actor checks exact binding/channel, seam phase, sealed admission and, as applicable, actual registered request or `diagnosticWriting`; both channel and actor use the same sealed immutable bytes and original deadline, rather than separately supplied values. `fixtureCheck` performs the full concrete context/provider/original lock/actual C bridge checks with the proper existing peer requirement. Calling only `FixtureContext.check` would omit these server guards and is insufficient. It returns a result asynchronously to the SAME write queue. Caller send/deadline structured tasks never await orphan `validatorTask.value`: original deadline helper uses `withThrowingTaskGroup`, and a noncooperative child can prevent structured scope exit. On callback, fence exact head object, binding and lease, sticky generation/identity, local terminal/cancel/close and original cutoff. Ignore late success or failure of a terminal/superseded head; it cannot write, resume or release twice, or reopen anything.

Frame header and immutable `Data` are created once, offset maintained by the head. Only after validation returns and all fences pass does the original writer obtain a duplicate operation FD, open a synchronous `withUnsafeBytes` scope, make **one** `Darwin.write` attempt, end the pointer scope and close that duplicate after the call. No `UnsafeBufferPointer`, raw buffer pointer or FD survives an await or reaches an orphan validator. Successful short writes advance offset; EINTR advances no offset; both return to full validation before another attempt. Complete frame => success; terminal error or deadline after partial bytes => close, no subsequent frame, no reconnect or resend. Do not forcibly close/reuse an FD under a live syscall.

Each admitted job owns exactly one checked continuation and reservation, with explicit terminal/resolved/released state; all close-before-enqueue, enqueue, validation, writing, cancellation, success and late-callback races must settle at most once and release exactly once. A failure flushes queued jobs; while async validation is blocked, queue housekeeping must settle jobs without waiting for its result. Close/revoke synchronously marks local state and shuts down the socket, preventing new admission or authorized attempts; cancellation of validation is only a hint. The queue may itself be inside a blocking physical `write`: ordinary shutdown is expected to wake it, not guaranteed. Neither prompt physical syscall completion nor universal resource quiescence is promised if OS/C does not return. Original context/provider/inspector/lock stay alive while any check could use them; existing shared release and eventual teardown must not close an inspector during synchronous C use. Report cleanup unconfirmed if the relevant work never returns.

## Deadlines, failure status and locking

Use one original budget established **before enqueue**, including scheduling delay, queue wait, checks, callback delay and every physical attempt/retry; never renew at head or after partial/EINTR. Handshake uses its existing pending deadline; serving creates the existing `FrameDeadline` at server send admission with the same `lifetimeStart` (3-second frame and shared 45-second lifetime). Diagnostic cutoff is the minimum of its existing 2-second/idle cap and frame/lifetime remainder. Reuse existing deadline/shutdown machinery; preserve conversion from remaining duration to C monotonic deadlines, never compare DispatchTime absolute epoch to C CLOCK_MONOTONIC. A cutoff already expired cannot admit or write.

Extend the SAME existing revocation/terminal record with a typed first terminal cause. On a context denial, record the actual first typed reason (e.g. repository changed or lock lost) in that same record before the queue failure shuts down the socket; later generic EOF/revoked observations do not overwrite it. A genuinely earlier independent terminal event remains first. The actor's diagnostic/status getter reads this same record, not a separate auth callback or parallel lifecycle store. On bound EOF, distinguish clean peer EOF with local descriptor still open from channel already locally closed/revoked/terminal: local failure returns status 1 even if receive wakes before writer catch reaches the server actor; clean peer EOF may remain status 0. Do not log raw profile records or nonce.

Channel lock protects only channel-local identity, descriptor and byte-accounting transitions. Never call `revocation.check`/`revoke`, invoke another owner, or await actor/provider while holding it; specifically no channel-lock -> revocation-lock inversion against existing revoke order. Capture local transition, unlock, then publish a known typed context denial to that same record before socket shutdown using a race-safe first-cause protocol; ordinary close may have no typed cause. Immediate local close is authoritative for stopping writes, and status must not incorrectly become clean while record publication is pending. These ordering details need implementation-level verification, not a promise of atomicity between external context and syscall.

State may change between completed validation and the next syscall or while it blocks, and already emitted bytes cannot be recalled. No claim of atomic external-state-to-byte authorization or guaranteed syscall interruption.
